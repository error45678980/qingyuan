# v2.0 产品决策裁定（交付总监）

> 对应 `01_PRD_v2.md` 第 6 节待确认问题。以下为最终决定，架构师直接按此设计，不再回问。

## Q-1 身份标识 —— 决定：**设备 ID 为准，昵称仅用于展示，重名不合并**

- 客户端首次启动生成 `client_id = uuid4()`，持久化到 `~/.Qingyuan/config.json`，此后每次启动复用。
- 所有请求带 `X-Client-Id` 头；服务端首次见到该 `client_id` 时登记用户，返回 `token`（可长期复用，存本地配置）。
- **作者归属判定以 `client_id` 为准**，不以昵称为准。两台机器都叫「小明」＝两个不同用户，各自只看得到自己的「我的」。
- 兼容历史数据：`author_node_id` 为空的旧记录，作者判定回退为「昵称相同」，但**仅用于展示管理按钮**，不可用于删除/私密化等破坏性操作以外的新增权限。
- 理由：昵称合并会让任何人输入「Tester」就获得他人泡泡的管理权，这与 R-02/R-06 的隐私目标直接冲突。

## Q-2 已解决的泡泡 —— 决定：**保留记录，`status='resolved'`，对他人隐藏**

- 服务端不物理删除；`GET /api/v2/bubbles` 默认只返回 `active` / `saved_public`。
- 作者可在「我的 → 已解决」看到历史，对话只读。
- 理由：情感内容误删不可恢复的代价过高；同时保留审计能力。

## Q-3 私密保存 —— 决定：**私密内容只存本地，服务端同步改为"对他人不可见"**

- 私密保存时：本地 `status='saved_private'`；服务端把该泡泡的可见性改为 `private`（只有作者能读），**不额外上传任何对话内容**。
- 若该泡泡从未上传过（纯离线创建），则私密保存后**不上传**。
- 理由：最小暴露面。已被他人看过的内容无法收回，这一点在 PRD 里如实说明即可，不承诺"撤回"。

## Q-4 冲突规则 —— 决定：**作者操作优先，其余服务端优先（按 `version` 号）**

- 每条泡泡带 `version` 整数，服务端每次变更 +1；客户端提交时带 `base_version`。
- 作者本人对**自己泡泡**的 `resolve` / `save` 操作无条件生效（覆盖服务端状态）。
- 非作者操作（回复、聊天）遇到 `version` 冲突时以服务端为准，客户端拉取后覆盖本地。
- 离线队列按入队顺序 FIFO 重放；同一 `client_id` 的重复提交按 `op_id` 幂等去重。

## 附加裁定

- **测试框架**：用标准库 `unittest` 编写，同时保持 pytest 兼容（`unittest.TestCase` + 纯 `assert`）。验收命令为 `python -m unittest discover -s tests -v`，不强制安装 pytest（当前环境未装，不应为跑测试引入新依赖）。
- **视觉目标**：以 `02_视觉规格.md` 为准 —— 圆形发光泡泡 + 流式布局 + 浮动动效，不要沿用现有的矩形卡片。
- **深色模式**：PRD 已列 Out of Scope，本次不做，但配色必须集中在 `theme.py`，为将来留口。
- **安全提示**：`config/secrets.local.py` 内含一条真实的云数据库连接串与 Flask SECRET_KEY，属于历史 Web 分支遗留物。必须加入 `.gitignore`，并在交付说明中提醒用户轮换密钥。本次不读取、不使用该文件。
