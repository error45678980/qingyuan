# 情缘 v2.0 — 交付总监审计报告（改进基线）

> 审计人：齐活林（交付总监）
> 审计方式：逐文件静态走查 + 本地数据库实测 + 离屏渲染验证
> 结论：项目**可运行但处于"数据错乱 + 体验卡死"状态**，必须做一次结构性重构，而非打补丁。

---

## 一、实证发现（有证据，非猜测）

### P0-1 客户端数据库列序错位 —— 全站数据错乱的根因（最严重）

`src/database.py` 的迁移方式是 `ALTER TABLE ADD COLUMN`，新列被追加到**表末尾**；而所有查询都用 `SELECT *` + 位置下标读取。

实测本机库列序（迁移后）：
```
id, author_nickname, content, emotion_tag, reply_mode, status, created_at, resolved_at, author_node_id
```
代码却假设列序为：
```
id, author_nickname, author_node_id, content, emotion_tag, reply_mode, status, created_at, resolved_at
```

结果：`row[2..6]` 全部错位一格。

- `src/ui/bubble_widget.py` 中 `self.content = bubble_data[3]` 实际取到 `emotion_tag`
- `self.emotion = bubble_data[4]` 实际取到 `reply_mode`（"single"/"dialog"）→ 取不到配色，全部 fallback 成灰色
- `self.created_at = bubble_data[6]` 实际取到 `status`（"active"）→ 卡片时间显示为空

离屏渲染已复现：泡泡墙上所有卡片均为灰色空白。

历史日志 `app_log.txt` 中的崩溃 `table bubbles has no column named author_node_id` 也是同一处迁移缺陷的早期表现。

**修复要求**：彻底废弃位置下标，统一使用 `sqlite3.Row` + 显式列名；迁移改为"建新表 → 按列名拷贝 → 换表"，保证新旧库列序一致。

### P0-2 "私密保存"的泡泡永久消失（数据黑洞）

`save_bubble_as(is_public=False)` 把状态改为 `saved_private`，而 `get_all_active_bubbles()` / `get_bubbles_by_emotion()` 只查 `active` / `saved_public`。
**全代码库没有任何入口能查 `saved_private`**。用户一旦选私密保存，这条泡泡连同全部对话就再也看不见了 —— 直接违背需求文档 2.6 节"私密保存（仅自己可见）"。

### P0-3 UI 线程同步网络请求 → 界面周期性假死

`src/ui/main_window.py` 用 `QTimer(3000)` 在主线程调用 `_load_bubbles()`，其中：
- `self.network.is_online()` 被调用 **2 次**（一次判断同步、一次判断状态文案）
- `fetch_bubbles()` 一次
- `requests` 超时 5 秒

服务器不可达时，每 3 秒卡 15 秒；即使正常也要每 3 秒销毁重建全部卡片，滚动位置丢失、闪烁、CPU 空转。

### P0-4 对话接收者算错，消息发给自己

`src/ui/chat_window.py`：
```python
receiver = author if self.nickname != author else bubble[1]   # bubble[1] 就是 author 自己
```
作者自己打开对话窗口时，收件人是作者本人。
且 `src/main.py` 的 `_show_chat(self, bubble_id, replier)` **完全忽略 `replier` 参数**，无论谁点进来，对话对象都是作者。

### P0-5 服务端隐私泄漏

`POST /api/bubbles/<id>/chat` 返回该泡泡下**所有人**的聊天记录给任意调用方，不做参与者校验。私密对话形同公开。

### P0-6 单次回复规则只在客户端生效

`has_replied()` 只在 UI 层校验，服务端 `post_reply` 无任何限制；同一昵称可无限次回复。且服务端允许任意人用任意 `id` 覆盖他人泡泡（`INSERT OR REPLACE`）。

## 二、功能缺口

| 编号 | 缺口 | 依据 |
|------|------|------|
| P1-1 | 没有"我的泡泡"入口，作者找不到自己发过的泡泡（含已保存的） | 需求 2.6 |
| P1-2 | 无搜索 | 使用规模变大后必需 |
| P1-3 | 全量拉取、无分页、无增量同步 | 服务器数据会无限增长 |
| P1-4 | 离线时发布/回复只在本地留痕，联网后不会补同步 | 需求 3.2 |
| P1-5 | 删除泡泡无"爆破动画" | 需求 2.6 明确要求 |
| P1-6 | 无新泡泡提示 / 未读标记 | 需求 2.5 |
| P1-7 | 固定两列网格（`cols = 2`），窗口放大浪费空间、缩小被挤压 | 体验 |
| P1-8 | 每次刷新销毁重建全部卡片，滚动位置丢失、闪烁 | 体验 |

## 四、v2.0 验收基线（团队必须全部满足）

1. 泡泡墙任意卡片能正确显示：内容、情感配色、发布时间、回复模式
2. "我的"页面能看到：我发布的 + 我私密保存的 + 我公开保存的泡泡，且私密内容他人不可见
3. 服务器完全不可达时：界面**不卡顿**，3 秒内可正常浏览本地缓存，并有明确离线提示
4. 断网期间发布/回复，恢复网络后自动补同步成功
5. 单次回复模式：同一用户第二次回复被服务端拒绝（HTTP 409），客户端给出友好提示
6. 私密对话：第三方调用 API 拿不到他人聊天内容（返回 403/过滤）
7. 作者自己打开对话窗口，收件人是正确的对话方
8. 解决泡泡有爆破动画；卡片按窗口宽度自适应列数
9. `pytest` 全绿，覆盖：数据库读写与迁移、单次回复规则、私聊隔离、离线队列补同步
10. 一键启动脚本可用（不依赖硬编码绝对路径）

## 五、约束

- 技术栈保持 **PyQt5 + Flask + SQLite**，不引入前端框架，不改变"双击即用"的桌面形态
- 入口保持 `python server.py` / `python src/main.py` 不变
- 必须兼容本机已有数据库（6 条泡泡记录不得丢失）
- 所有 UI 文案保持中文
